## 🛒 장보기 타임어택

위에서 내려다본 마트를 캐릭터가 직접 돌아다니며 장을 봅니다. 시작할 때 **테마 3가지** 중 하나를 골라요.

| 테마 | 구성 | 이야기 |
|---|---|---|
| 🌙 마감 직전 | 무한 모드 | 마트 문 닫기 직전! 단계마다 마감 방송·문자 속 상황이 바뀌어요 |
| 🏠 자취생의 일주일 | 7일 스토리 + 엔딩 | 이사 첫날, 첫 집밥, 시험 야식, 감기, 집들이, 엄마 방문, 나에게 주는 선물 |
| 👨‍🍳 요리 서바이벌 | 5라운드 토너먼트 + 우승 엔딩 | 예선 카레 → 브런치 → 해물 → 디저트 → 결승 풀코스. 다른 손님은 경쟁 참가자 |

스토리 테마는 단계마다 이야기에 맞는 상품 목록이 나오고, 최고 기록은 테마별로 따로 저장돼요.

1. **방향키 / WASD**로 움직이거나, 지도에서 가고 싶은 곳을 **클릭·탭**하면 그곳까지 걸어가요.
2. 목록에 있는 상품 위를 **지나가면 자동으로 담겨요**. 2개가 필요하면 한 번 벗어났다가 다시 밟아요.
3. 목록에 없는 상품을 밟으면 **3초 감점**, 돌아다니는 **다른 손님**과 부딪히면 잠깐 멈춰요.
4. 다 담았으면 오른쪽 아래 **계산대**로 가면 단계 클리어!

단계가 올라갈수록 목록이 길어지고 손님이 늘어나며, 매장 진열은 단계마다 바뀝니다.

## 👗 백스테이지 퀵체인지

패션쇼 백스테이지의 스태프가 되어, 런웨이에서 돌아온 모델에게 정해진 착장을 빠르게 입힙니다.

1. 모델이 피팅 자리에 서면 **룩 카드**(입혀야 할 옷 목록)가 보여요.
2. 상의·하의·아우터 행거, 신발장, 액세서리 테이블을 돌며 맞는 옷 위를 지나가 **손에 들어요** (최대 5벌, 누르면 되돌려놓기).
3. 옷을 들고 모델에게 다가가면 **저절로 입혀져요**. 룩 카드와 맞는지 확인하고 **Space**나 **Enter**(휴대폰은 **런웨이로** 버튼)로 내보내요.
4. 틀린 옷을 입혔거나 모델의 제한 시간이 끝나면 **목숨(♥) −1**. 세 개를 모두 잃으면 쇼가 중단돼요.

| 쇼 | 입힐 옷 | 모델 수 | 동시에 | 룩 카드 |
|---|---|---|---|---|
| 1 | 상의·하의·신발 | 3명 | 1명 | 계속 보임 |
| 2 | + 액세서리, 무늬 등장 | 4명 | 2명 | 계속 보임 |
| 3~ | + 아우터 | 5~6명 | 3명 | 도착 후 5초만 (다시 보기 −3초) |

색만 살짝 다르거나(빨강/분홍, 파랑/남색) 무늬만 다른 **비슷한 옷 함정**을 조심하세요.

## 📝 회고

> 회고는 지나간 학습 과정을 돌아보며 배우고 성장하기 위해 씁니다.
> 오늘 새롭게 알게 된 것, 도움이 된 방법, 잘 안된 점과 보완할 점을 정리했어요.

### 1. 새롭게 알게 된 것

- **게임의 최소 재료는 세 가지다.**
  - **보이는 것:** 점수판, 게임판, 버튼
  - **상태:** 점수, 남은 시간, 진행 중인지 끝났는지
  - **규칙:** 무엇을 하면 상태가 어떻게 바뀌는지
  - 두 게임 모두 이 세 가지로 나눠 설명할 수 있었다.
- **게임은 "상태 바꾸기 → 다시 그리기"를 1초에 약 60번 반복하는 구조(게임 루프)로 돌아간다.**
- **HTML, CSS, JavaScript는 하는 일이 다르다.**
  - **HTML:** 화면 뼈대
  - **CSS:** 디자인
  - **JavaScript:** 게임 동작
  - HTML이 `id`로 이름표를 붙이면 CSS는 모양을 입히고, JavaScript는 그 이름표를 찾아 숫자를 바꾼다.
- **GitHub를 쓰는 기본 흐름을 알게 됐다.**
  - 저장소 → 커밋(바뀐 내용 기록) → 푸시(GitHub에 올리기)
  - Claude가 내 저장소에 올리려면 **Claude GitHub App 설치(권한)**가 필요하다.
- **github.com과 github.io는 다르다.**
  - **github.com:** 코드를 보는 곳
  - **github.io (GitHub Pages):** 게임이 실행되는 웹사이트
  - Pages는 Settings에서 직접 켜야 한다.
- **저장소 하나에 여러 게임을 둘 수 있다.** 게임마다 폴더를 나누고, 맨 위에 게임 목록 페이지를 두면 된다.

### 2. 알고 있었지만 더 자세히 알게 된 것

- **"재미있는 게임 만들어줘"처럼 막연하게 요청하면 결과도 단순하다.**
  - 처음 만든 장보기 게임은 내가 생각한 "캐릭터가 마트를 돌아다니는 게임"이 아니라 클릭만 하는 게임이었다.
  - 다음 항목을 구체적으로 정하고 나서야 원하는 게임이 나왔다.
    - **시점:** 위에서 내려다보기
    - **조작:** 방향키, 클릭
    - **담는 방식:** 지나가면 자동으로 담기
    - **방해 요소:** 손님, 바뀌는 진열
- **파일을 나누든 합치든 데이터 양은 거의 같다.**
  - 나누기의 장점은 크기가 아니라 다음과 같다.
    - 코드를 읽기 쉽다.
    - 바뀐 파일만 다시 받는다(캐시).
    - 고친 기록을 보기 쉽다.
  - 합치기의 장점은 파일 하나로 보내고 바로 실행할 수 있다는 것이다.
- **게임에는 규칙 말고도 스토리, 디자인, 재미 요소가 필요하다.**
  - 점검해 보니 디자인과 재미 요소(시간 압박, 방해 요소, 보너스)는 있었다.
  - **스토리가 가장 약했다.**
  - 그래서 장보기 게임에 테마 3가지(마감 직전, 자취생의 일주일, 요리 서바이벌)를 넣었다.

### 3. 기억하기 위해 구조화한 것

| 기획 질문 | 🛒 장보기 타임어택 | 👗 백스테이지 퀵체인지 |
|---|---|---|
| **보이는 것**<br>화면에 무엇이 있어야 하나? | 마트 지도, 상품, 캐릭터·손님, 장보기 목록, 타이머, 점수판 | 백스테이지 지도, 행거, 옷, 모델, 피팅 패널, 룩 카드, 목숨 |
| **상태**<br>어떤 상황이 보여야 하나? | 남은 시간(5초 이하 빨강), 담은 수/필요한 수, 다 담으면 계산대 깜빡임 | 모델별 남은 시간(시간 원), 맞게 입히면 ✓, 카드 가려짐 ?, 목숨 ♥ |
| **규칙**<br>무엇을 하면 무엇이 바뀌나? | 밟으면 담기, 목록에 없는 상품은 −3초, 손님과 부딪히면 멈춤 | 밟으면 들기, 다가가면 입히기, 틀리면 목숨 −1 |
| **규칙**<br>언제 끝나나? | 다 담고 계산대에 가면 클리어, 시간 0이면 끝 | 모델을 다 내보내면 피날레, 목숨 0이면 끝 |

### 4. 도움이 되었던 방법

- **Claude Code와 대화하며 기획하기**
  - Claude가 시점, 조작, 담기 방식, 실패 규칙 같은 **선택지 질문**을 해 줘서, 막연했던 아이디어를 구체적으로 정할 수 있었다.
- **직접 플레이해 보고 불편한 점 말하기**
  - 예: "방향키로 옷을 모으고 마우스로 입히느라 시간이 지체된다"
  - 이런 피드백이 Space 한 번에 입히기로, 다시 **다가가면 저절로 입히기**로 이어졌다.
  - 직접 해 봐야 보이는 문제가 있었다.
- **같은 기준으로 두 게임 비교하기**
  - 보이는 것·상태·규칙, 스토리·디자인·재미 요소로 나눠 비교했다.
  - 두 게임의 공통 구조(이동, 길찾기, 단계별 난이도)와 차이(시간 vs 목숨)가 잘 보였다.
- **코드를 역할별로 나눠 보기**
  - HTML, CSS, JavaScript를 따로 놓고 표로 정리하니 어느 줄이 무슨 일을 하는지 찾기 쉬웠다.

### 5. 잘 안된 점과 보완할 점

| 잘 안된 점 | 왜 안됐나 | 이렇게 보완하겠다 |
|---|---|---|
| 첫 게임이 내가 생각한 게임과 달랐다 | 장르와 조작 방식을 설명하지 않고 "쇼핑 게임"이라고만 요청했다 | 만들기 전에 **보이는 것·상태·규칙**을 먼저 적고 요청한다 |
| Claude가 GitHub에 올리지 못했다 (403) | Claude GitHub App이 저장소에 설치되지 않았다 | 새 저장소를 만들면 Claude App 권한부터 확인한다 |
| 게임 주소가 404였다 | GitHub Pages는 저장소 Settings에서 직접 켜야 한다는 걸 몰랐다 | 배포 체크리스트: 저장소 공개 → Pages 켜기 → 주소 열어 확인 |
| 과제 제출에서 링크가 거절됐다 | 제출란은 github.com만 받는데, github.io 주소를 냈다 | 저장소 주소를 제출하고, README에 플레이 링크를 넣는다 |
| 백스테이지 게임 조작이 불편했다 | 키보드(이동)와 마우스(입히기)를 섞어 써야 했다 | 한 가지 입력으로 끝까지 할 수 있게 설계하고, 직접 플레이해서 확인한다 |
